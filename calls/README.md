# Kishka-call — сервіс голосових дзвінків Kishka Messenger

Окремий легкий сервіс: лише пересилає кадри голосу між двома співрозмовниками (WebSocket, сирі бінарні кадри). Повідомлення,
сигналізація дзвінка («дзвонить», «прийняв») і відео лишаються на основному сервері Kishka.

## Налаштування на Render (форма «New Web Service», як на вашому відео)

| Поле | Що вибрати |
|---|---|
| **Name** | `Kishka-call` (адреса стане `https://kishka-call.onrender.com`; якщо Render додасть до назви цифри — використовуйте його адресу) |
| **Language** | `Node` |
| **Branch** | `main` |
| **Region** | **Frankfurt (EU Central)** — найближчий до України, затримка голосу буде найменшою. Основний сервер може лишатись у Virginia: голос іде телефон → Kishka-call → телефон, основний сервер у цьому не бере участі |
| **Root Directory** | порожньо, якщо цей код лежить у корені окремого репозиторію `Kishka-call`; `calls`, якщо він лежить у папці `calls/` основного репозиторію |
| **Build Command** | `npm install` (замість стандартного `yarn install`) |
| **Start Command** | `node server.js` (замість стандартного `yarn start`) |
| **Instance Type** | **Starter ($7/міс)** для надійних дзвінків. **Free** теж працює, але сервіс «засинає» через 15 хв без запитів, і перші ~50 с після пробудження голос іде запасним шляхом через основний сервер (як раніше) |
| **Environment Variables** | не потрібні (Render сам задає `PORT`) |
| **Advanced → Health Check Path** | `/healthz` |
| **Advanced → Auto-Deploy** | `On Commit` |

Якщо сервіс лежить у `calls/` основного репозиторію, у **основного** сервісу Render додайте в *Advanced → Build Filters → Ignored Paths*
рядок `calls/**`, щоб правки дзвінків не перезапускали основний сервер.

Після першого успішного деплою відкрийте `https://<адреса>/healthz` — має відповісти `Kishka-call ok`.
Адресу вставте в застосунок: файл `app/src/main/java/com/kishka/messenger/Voicechannel.kt`, рядок
`const val CALL_SERVER_URL = "wss://kishka-call.onrender.com"` (початок `wss://`, далі адреса без `https://`).

## Як це працює

* Телефон відкриває WebSocket і надсилає `{"t":"hi","me":"я@пошта","peer":"співрозмовник@пошта"}`.
* Кадр голосу пересилається співрозмовнику без змін, лише якщо той теж «зайшов» і вказав вас як співрозмовника.
* Сервіс повідомляє `{"t":"peer","on":true|false}`: поки співрозмовника на лінії немає, застосунок шле голос основним сервером — слова не губляться.
* Якщо співрозмовник «не встигає» (затримка росте), старі кадри відкидаються: краще крихітний пропуск, ніж відставання розмови.
* Сервіс нічого не зберігає й не пише пошту в журнал. `GET /stats` показує лише лічильники.
